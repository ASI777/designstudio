================================================================================
  EXAMPLE BUILD PROMPTS — by engineering branch
  Natural-language design requests real engineers type into the app's harness.
  ("build …", "design a …", "controller for …" → routed to the design pipeline)
================================================================================

HOW TO READ THIS FILE
  • DENSE prompts already specify most decisions → the harness asks few questions.
  • SPARSE prompts leave decisions open → the harness asks more (adaptive budget).
  • Each group lists the rough archetype + key parts the intent agent should reach.
  Use these to exercise the pipeline, seed the design memory, and demo the app.

================================================================================
  NOTES FOR DESIGNERS / TESTERS
================================================================================
  • Dense prompts are the fastest path to a clean first-pass design and the best
    seeds for the design memory (they verify in few refines → high quality).
  • Re-running a SIMILAR prompt after a successful one demonstrates the closed
    retrieve→reuse loop (fewer refines, fewer LLM calls — "designs better with use").
  • Safety-critical mains / high-voltage prompts (relays, meters, AC-DC) should
    always be reviewed for creepage/clearance after auto-layout — the verifier
    checks connectivity, not isolation distances.
  • After a build completes, run  /subsystem  then  /route  to place and route.
